# Сценарии пропусков и неоднозначностей

Частные правила поверх контракта `references/protocol_format.md`.
Цель — не ломать конвертер и не выдумывать факты.

## Метаданные

| Ситуация | Действие |
|----------|----------|
| Дата не названа или несколько дат без пометки «встреча» | `Дата: не указан` |
| Участники не перечислены | `Участники: не указан` |
| Участники даны намёком («команда продукта») | оставь формулировку из входа; не расширяй до ФИО |
| Тема не сформулирована явно | возьми краткую тему из доминирующего вопроса встречи; если и этого нет — `Тема: не указан` |

## Обсуждение

| Ситуация | Действие |
|----------|----------|
| Только решения/задачи, без дискуссии | `нет данных` |
| Повторы и черновые фразы | сожми до нейтральных абзацев без потери фактов |
| Противоречивые черновые формулировки одной темы | отрази обе позиции кратко; не выбирай «победившую», если решение не зафиксировано |

## Решения

| Ситуация | Действие |
|----------|----------|
| Явных решений нет | `нет данных` |
| Фраза похожа и на обсуждение, и на решение | в «Решения» только если есть явный итог («решили», «утвердили», «договорились») |
| Решение без исполнителя | оставляй в «Решения»; задачу создавай только если есть поручение |

## Задачи

| Ситуация | Действие |
|----------|----------|
| Поручение есть, ответственный не назван | `Ответственный` = `не указан` |
| Срок не назван или «скоро» / «asap» | `Срок` = `не указан` |
| Несколько человек без указания, кто именно | `Ответственный` = `не указан` (не пиши всех через «/») |
| Срок относительный («через неделю») при известной дате встречи | оставь относительную формулировку как во входе; не вычисляй календарную дату |
| Несколько сроков у одной задачи | `Срок` = `не указан` |
| Задача сформулирована туманно («разобраться с этим») | переформулируй по ближайшему явному предмету из контекста; если предмета нет — всё равно одна строка таблицы с доступным текстом |

## Конфликт «решение vs задача»

- Утверждённый факт без поручения → только «Решения».
- Поручение с действием → строка в «Задачи»; при необходимости краткий дубль сути в «Решения», если так сказано во входе.
- Не создавай задачи «от себя» для каждого пункта обсуждения.
